## 3. Critical Fixes Applied

During the evaluation, we uncovered and isolated two critical integration-layer bugs that had previously been masking as PyTorch/CUDA hangs during live inference:

1. **Windows Subprocess Pipe Deadlock:** The `uvicorn` server was silently hanging entirely exactly at the 65th request. After ruling out zero-variance PyTorch hangs and Windows socket exhaustion, we traced it to an OS-level I/O deadlock. The test script had spawned the server with `stdout=subprocess.PIPE` but wasn't continually reading from it. Exactly at 65 requests, the ~4KB logs generated by Uvicorn completely filled the Windows pipe buffer, instantly deadlocking the entire FastAPI event loop whenever it tried to `print` or `log` anything further. We removed the unread pipe, fixing the hang permanently. 
   - **File Changed:** `server/test_http_integration.py`

2. **DecisionEngine Corroboration Edge-Case:** We discovered the FROZEN sensor scenario successfully identified the temporal fault (score=25), but was being bypassed into a NORMAL reading. The engine dictates that temporal faults must override spatial corroboration *if the confidence score is strictly `< 25`*. Because a frozen sensor gives a penalty of exactly 75 (resulting in a score of 25), the strict `< 25` threshold caused the engine to trust the buddy stations (which were also injected with identical frozen readings for the test setup) over the frozen status. We adjusted the override logic to correctly be `<= 25`.
   - **File Changed:** `server/engine/decision_engine.py`

3. **Proactor Event Loop Safety:** While investigating the Uvicorn hang, we implemented `WindowsSelectorEventLoopPolicy` during startup to fully harden the backend against Windows `IocpProactor` socket limits.
   - **File Changed:** `server/main.py`
